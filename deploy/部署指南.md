# 部署指南(Ubuntu/Debian + Nginx + Gunicorn + SQLite)

部署结果:浏览器访问 `http://你的域名:8080` 打开链域。
原有的 Dify 继续占 80 端口,两者并存互不影响。

---

## 0. 准备

- 一台 Ubuntu/Debian 云服务器,有 root/sudo
- 一个已解析到该服务器 IP 的域名(Dify 在用的那个就行)
- 安全组/防火墙放行 **8080** 端口(80 留给 Dify)
- 本地装有 Node.js 16+ (用于 build 前端)

> **为什么是 8080**:Dify 官方 Docker Compose 启动后会占用宿主机的 80 端口,
> 链域监听 8080 避免冲突。两者共用同一个域名,只是后缀加端口号。

---

## 1. 本地: 构建前端

```bash
cd frontend
npm install        # 第一次需要
npm run build      # 生成 frontend/dist/
```

完成后 `frontend/dist/` 是要上传的静态文件目录。

---

## 2. 本地: 把项目传到服务器

服务器目标目录: **`/var/www/lianyu/`**,只需要三块东西:

```
/var/www/lianyu/
├── backend/           # 整个 backend 目录
├── dist/              # 前端 build 出的 frontend/dist
└── deploy/            # 部署配置(本目录)
```

### 选择 A: 用 scp(Windows 自带,PowerShell 即可)

```powershell
# 在项目根目录执行
ssh root@你的服务器IP "mkdir -p /var/www/lianyu"

scp -r backend         root@你的服务器IP:/var/www/lianyu/
scp -r frontend/dist   root@你的服务器IP:/var/www/lianyu/
scp -r deploy          root@你的服务器IP:/var/www/lianyu/
```

### 选择 B: 用 rsync(更快,支持增量)

```bash
rsync -avz --delete backend/       root@IP:/var/www/lianyu/backend/
rsync -avz --delete frontend/dist/ root@IP:/var/www/lianyu/dist/
rsync -avz --delete deploy/        root@IP:/var/www/lianyu/deploy/
```

### 选择 C: 打包传一次

```powershell
# 本地打包
tar -czf lianyu.tgz backend frontend/dist deploy
scp lianyu.tgz root@IP:/tmp/
ssh root@IP "mkdir -p /var/www/lianyu && tar -xzf /tmp/lianyu.tgz -C /tmp && \
  mv /tmp/backend /tmp/deploy /var/www/lianyu/ && \
  mv /tmp/frontend/dist /var/www/lianyu/ && rm -rf /tmp/frontend"
```

## 3. 服务器: 一键安装

SSH 上服务器,执行:

```bash
sudo bash /var/www/lianyu/deploy/server_setup.sh 你的域名.com
```

脚本会自动:
1. 装 Python3 / pip / nginx
2. 创建 venv 并装依赖(含 gunicorn)
3. 生成随机 SECRET_KEY / JWT_SECRET_KEY 到 `backend/.env`
4. 注册 systemd 服务并启动后端
5. 写入 Nginx 站点并 reload

完成提示后直接浏览器打开 `http://你的域名.com:8080` 即可。

默认管理员:`admin / admin123`,**登录后第一件事改密**。

> 如果浏览器打不开,先确认两件事:
> 1. 云服务商的**安全组**入站规则已经放行 8080 端口
> 2. 服务器系统防火墙(ufw 等)也放行了 8080:`sudo ufw allow 8080/tcp`

## 4. 日常运维

### 看后端日志
```bash
sudo journalctl -u lianyu-backend -f                  # systemd 日志
sudo tail -f /var/log/lianyu/error.log                # gunicorn 错误
sudo tail -f /var/log/nginx/lianyu.error.log          # nginx 错误
```

### 重启服务
```bash
sudo systemctl restart lianyu-backend     # 重启后端
sudo systemctl reload nginx               # 重载 nginx 配置
```

### 更新代码
本地改完代码再次执行第 2 步上传,然后:
```bash
# 前端只换静态文件不用重启
# 后端改了代码:
sudo systemctl restart lianyu-backend
# 如果改了 requirements.txt:
cd /var/www/lianyu/backend && sudo -u www-data ./venv/bin/pip install -r requirements.txt
sudo systemctl restart lianyu-backend
```

### 备份 SQLite
```bash
sudo cp /var/www/lianyu/backend/app.db ~/lianyu-$(date +%F).db
```

## 5. 常见问题排查

**打开 :8080 没反应/超时**
- 云服务商安全组没放行 8080(最常见)
- 服务器防火墙: `sudo ufw status`,如果是 active 就 `sudo ufw allow 8080/tcp`
- 检查 nginx 是否监听: `sudo ss -tlnp | grep 8080`

**Nginx 启动失败提示 bind() to 0.0.0.0:80 failed**
- 默认 default 站点想抢 80,而 80 被 Dify 占了。解决:
  `sudo rm -f /etc/nginx/sites-enabled/default && sudo systemctl restart nginx`
  (server_setup.sh 已经做了这一步,正常不会触发)

**打开 :8080 是 502 Bad Gateway**
- `sudo systemctl status lianyu-backend` 看后端是否在跑
- `sudo journalctl -u lianyu-backend -n 50` 看启动报错(多半是依赖装失败或 .env 配置错)

**打开根域名(:80) 看到的还是 Dify**
- 这是预期的,Dify 仍然占 80。链域必须带 `:8080` 访问

**API 请求 404**
- Nginx 里 `location /api/` 配置丢了,检查 `/etc/nginx/sites-available/lianyu`
- 后端实际端口要和 nginx `proxy_pass` 的 5000 一致(也别和 Dify 内部端口撞,5000 一般安全)

**5000 端口已被占用**
- `sudo ss -tlnp | grep 5000`,如果是 Dify 在用,改一个其他端口:
  改 `lianyu-backend.service` 的 `--bind 127.0.0.1:5001`,
  同步改 `lianyu.nginx.conf` 的 `proxy_pass http://127.0.0.1:5001;`,
  然后 `sudo systemctl daemon-reload && sudo systemctl restart lianyu-backend && sudo systemctl reload nginx`

**SQLite 写不进去 / database is locked**
- `sudo chown -R www-data:www-data /var/www/lianyu/backend`
- 高并发场景换 MySQL: 在 `.env` 改 `DATABASE_URL`

**改 SECRET_KEY 后所有用户掉线**
- 这是正常的,JWT 失效。生产首次部署改一次后就别再动。
